背景

Agent 写代码的速度，取决于它读到的文档对不对

Claude、Codex、Cursor 正在成为文档的主要读者。这条链路上的三方都有没被解决的问题。

开发者

Agent 引用过期的 API，而且说不清出处

模型训练数据有截止日期。框架每月都在变，Agent 写出的代码常常基于旧版本，错了也无从查证是哪一份文档说的。

团队与采购

按 Token 计费的上下文，账单无法预估

同样一次查询，返回长短不同，费用就不同。团队也很难控制 Agent 能读哪些来源，私有资料的边界不清楚。

文档维护者

知识被 AI 大量消费，维护者一分钱拿不到

最有价值的文档来自框架作者、API 提供方和行业专家，他们最没有理由免费给第三方平台持续维护。供给因此腐化。

功能

一个为 Agent 准备的、可审计的知识层

Web、REST API、远程 MCP、CLI/SDK 四个入口共用同一套身份、版本、访问规则、计量和审计，均已在代码中实现。

Agent 只需要两次调用

resolve-library-id(libraryName: "next.js") → /vercel/next.js · verified · trust 92
query-docs(libraryId: "/vercel/next.js", query: "cache components") → 6 段上下文 · 每段带来源 URL、章节、版本号

第二步必须指定一个明确的库。这个约束让每一次计费都对应到唯一的知识库版本，是分成能够成立的技术前提。

始终最新
按来源变化创建不可变版本，按日或按周自动刷新；刷新失败时旧版本继续服务。
可信目录
公开库经来源、权利与安全审核，带 Trust Score 和 Benchmark Score；所有权通过仓库权限或 DNS 认领。
可追溯
每段上下文保留来源 URL、文档、章节和版本，Agent 的回答能逐句落到出处。
可独立验证
版本、每日审计链头和发布者结算单的摘要写入 Aptos 主网，第三方不调用 Re0 即可校验。
可治理
私有仓库、Notion、PDF 只服务所属工作空间；访问规则同时约束 Web、REST 和 MCP。
多种来源
GitHub、网站（含 JS 渲染）、llms.txt、OpenAPI、Notion、PDF（含扫描件 OCR），以及嵌入官网的问答插件。

1 Call

一次成功的检索

0 Call

空结果与失败不收费

返回零条结果的查询不计费；认证失败、参数错误、访问拒绝和平台错误也不计。页面浏览和 Dashboard 操作从不计费。

按新增

建库只为新内容付费

每次发布版本按新解析的内容折算 Calls，来源没变化不计费，平台升级引起的重建也由平台承担。

扣减顺序固定：先扣当期套餐额度，再扣调用包余额。套餐额度在账期末清零，调用包余额一直保留。

发布者收益

满足条件的专家库，按被调用次数分成

分成不是所有公开库都有。库要带「专家库」标签、所有者要在付费订阅中，调用也要来自其他工作空间。满足这些前提的调用，才进入当期分成池，按次数线性分给库的所有者。

  1. 维护者发布专家库

    公开库通过审核并有明确所有者，再申请专家库标签，由管理员批准。所有者工作空间需保持 Pro 订阅。

  2. Agent 调用更多

    目录更全、更新更及时，开发者把更多查询交给 Re0。

  3. 收入与分成池增长

    订阅和调用包收入上升，分成池随之变大，每次调用都留下可复算的收益事件。

  4. 更多维护者加入

    收益在 45 天持有期后可转为 Calls，或满 $20 提现到 PayPal，吸引下一批维护者。

参与分成的前提

库的条件

每次调用时实时判断，任一项不满足，这次调用就不产生收益

  • 公开且已发布，未被安全暂停
  • 有明确所有者：工作空间建库时已验证来源，或已完成所有权认领；平台自建库不参与
  • 带「专家库」标签：所有者申请、管理员按审核清单批准，可被撤销
  • 所有者工作空间处于付费订阅

调用的条件

只有其他用户真实用到这个库的调用才计入

  • 只计返回了结果的 query-docs；resolve-library-id、空结果和匿名试用都不计
  • 所有者自己的调用不计；与所有者同一付款人或同一管理者的关联工作空间也不计，关账时按最新关联关系再核对一次
  • 同一调用方对同一个库每天最多 200 次计入分成，超出的照常计费、不产生收益

结算

按账期计算，收益不追溯到满足条件之前

  • 分成池 = 当期净收入 × 可分成调用占全部计费调用的比例 × 20%，按调用次数线性分配，不按 Trust Score 加权
  • 关账时库处于暂停状态，当期收益作废
  • 45 天持有期后，任意金额可转为不过期的 Calls，或满 $20 申请提现到 PayPal

申请专家库标签时，库还要公开、已发布、所有者在付费订阅中，且评测题集达到题数下限、当前版本的命中率达到下限（阈值由运营在后台配置）。申请被拒或标签被撤销后，7 天内不能重新申请。收益数据不进入检索和排序。

收益估算

一个专家库每月能分到多少

收益 ≈ 满足上述前提的调用次数 × 平台每个计费 Call 的平均净收入 × 20%。拖动滑块看不同调用量下的结果。

确定性归因

按 Token 计费、或一次查询融合多个库结果的服务，无法在没有分摊争议的情况下给单个知识库算钱。Re0 的每个计费单位都对应一个库的一个版本，分成可以用原始调用记录逐条复算。

可公开验证的账本

版本内容和结算单的摘要锚定在 Aptos 主网，配套的独立 Verifier 不依赖 Re0 的接口。发布者不需要信任平台，自己就能核对账单没被改过。

所有权认领

能拿到分成的人必须证明自己控制来源：GitHub 仓库要求 admin 或 maintain 权限，网站要求 DNS TXT 记录。镜像站和 Fork 抢不走收益。

排序保持中立

收益数据不进入检索、召回和排序；Trust Score 只决定能否参与分成，不决定分多少。目录质量不会因为分成机制而被博弈。

技术

发布是一次真正的数据库事务

Chunk 正文、全文索引和向量存在同一个 Postgres 里，并在同一个事务内写入。一个版本要么完整发布，要么完全不出现，不存在跨系统的中间状态。
